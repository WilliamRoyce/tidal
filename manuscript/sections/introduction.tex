\section{Introduction}
\label{sec:Introduction}

This is the introduction, and it should be a fairly long section in which the reader is introduced to the topic of the paper.
You should begin with a very broad brush stroke, and then narrow down to the specific topic of the paper.
It is \textit{critical} that you cite the relevant literature throughout~\cite{gertsenshtein1962wave}.
Think of it this way: the reader wants to
\begin{enumerate}
  \item know where to go for more information,
  \item understand the existing literature,
  \item understand the position that your paper occupies in the literature,
  \item not waste time reinventing the wheel.
\end{enumerate}
So you should be citing a lot.
Note that you should also refer to any figures or graphics which help to explain the topic, and these should be placed in the \texttt{figures/} directory.

%If you want to introduce an acronym, such as Einstein--Cartan (EC) theory,
%you should write it out in full the first time, and then use the acronym thereafter.
%Note the use of the long hyphen~\texttt{--} for name concatenation.

We use the $(+\,-\,-\,-)$ signature convention and natural units where $\hbar=c=1$.

The structure of the remaining sections is as follows.
In \cref{sec:Theory} we review the relevant theory.
In \cref{sec:Results} we describe our main results.
In \cref{sec:ConcludingRemarks} we summarise and discuss the implications.

\subsection{Equation formatting}
\label{sec:EquationFormatting}

Real scientific papers do not have a `methods' section.
This is a fiction which you learn in school.
Instead, each section title should refer to a real thing.
For example, this subsection demonstrates equation formatting conventions.

Equations should be dense in every section of the paper.
As a rough guide, you should have at least one equation per paragraph, and at most three display equations per paragraph.
Rather than display every equation, you should use inline equations such as $x=y$, $z=w$, $v=u$, and reserve display equations for important results.

All equations should be part of a sentence.
For example, the Lagrangian for general relativity in the Palatini formalism can be written
\begin{align}
  \lag_\mathrm{GR}
    &\equiv -\frac{1}{2}\Planck^2 R
     \simeq -\frac{1}{2}\Planck^2 \rR{}
            + \T{}{\mu\nu\sigma}\T{}^{\mu\nu\sigma}\,,
  \label{eq:NormalGR}
\end{align}
where $\Planck$ is the reduced Planck mass.
Notice the comma after the equation, because the sentence continues.
The next sentence might present a large system of equations, such as
\begin{subequations}
\label{eq:BigSystem}
\begin{align}
  \frac{\mathrm{d}x}{\mathrm{d}t}
    &\equiv 17x^7y^3+5x^6y^4-7x^4y^5-3x^4y^3 \nonumber\\
    &\quad +7x^4y^2+17x^3y^3+5x^2y^3+11x^3y^2 \nonumber\\
    &\quad -13x^2y^2+19xy^2-23x^2y+37xy+87\,,\\
  \frac{\mathrm{d}y}{\mathrm{d}t}
    &\equiv 5x^7y^3-11x^6y^4-3x^4y^5+11x^4y^3 \nonumber\\
    &\quad +23x^4y^2-53x^3y^3+2x^2y^3+17x^3y^2 \nonumber\\
    &\quad -107x^2y^2+xy^2-3x^2y+3xy+7\,.
\end{align}
\end{subequations}
Notice the comma after the first equation, and the full stop after the second.

When using tensor notation, you can use the \texttt{tensor} package to place indices flexibly, for example $\tensor{A}{_\nu}$ or $\tensor{h}{_\mu_\nu}$.
Total differentials should be typeset as $\mathrm{d}x$, not $dx$.

The teleparallel equivalent of general relativity (TEGR) Lagrangian can be written in terms of the irreducible torsion components as
\begin{align}
  \lag_\mathrm{TEGR}
    &\equiv \frac{4}{9}\Planck^2 \T[1]{\mu[\nu\sigma]}\T[1]^{\mu[\nu\sigma]}
           -\frac{1}{3}\Planck^2 \T[2]{\mu}\T[2]^{\mu} \nonumber\\
    &\quad +\frac{3}{4}\Planck^2 \T[3]{\mu}\T[3]^{\mu}\,,
  \label{eq:TEGR}
\end{align}
where $\T[1]{}$, $\T[2]{}$ and $\T[3]{}$ are the three irreducible parts of the torsion tensor.

By the way, don't be afraid to use footnotes.\footnote{They are a useful way to add extra information without breaking the flow of the text.}

\subsection{Code listings}
\label{sec:CodeListings}

If you want to include code listings, you can use the \texttt{listings} package.
Note however that in most papers, \texttt{Matplotlib} output should be saved as a PDF and included with \texttt{graphicx}, not pasted as a code listing.
