## RESOLVED: Energy measurement: support mixed\_\* Hamiltonian operators

**Status:** Fixed (Python measurement layer)

Added general `mixed_*` operator evaluation to `_energy.py`. Decomposition strategy:

- Parse `mixed_T_S1_S2_...` notation (time order + spatial orders per axis)
- Resolve time derivatives: order 0 → field, order 1 → velocity, order 2 → acceleration from EOM RHS
- For constraint fields: differentiate constraint equation (velocity sources → acceleration, field sources → velocity/acceleration)
- Apply spatial gradients sequentially after time resolution
- Wired into `_evaluate_hamiltonian_factor` dispatch for seamless integration

Also added `mixed_*` to operator validation in `json_loader.py`.

**Complementary Wolfram IBP optimization** (not yet implemented): Integration by parts on the Lagrangian before the Legendre transform could reduce mixed operators at the source. The Python handler is the primary mechanism; IBP is an optimization for cleaner JSON

## OPEN: Pre-decomposition reduction for faster GW derivation

**Status:** Open (optimization)
**Priority:** Low
**Labels:** enhancement, performance

Benchmark (2026-02-28) of GW plane-wave derivation (18 min total):

- xPert + VarD: 0.4 sec (0%) -- abstract symbolic phases are fast
- DecomposeToComponents: 469 sec (42%) -- converts abstract EOM to 10 component equations
- DecomposeScalarExpression (canonical): 634 sec (57%) -- Hamiltonian decomposition

**Pre-linearization reduction is NOT worth it** since xPert+VarD take <1 sec.

**Actual optimization:** Per-component early exit in `DecomposeToComponents`. After `ToBasis` but before expensive `Expand`, zero transverse Derivative patterns. If the component is identically zero, skip remaining steps. For GW with plane-wave reduction, 8 of 10 components would short-circuit, potentially saving ~80% of decomposition time.

Requires modifying `ComponentDecompose.wl` (`ExtractTensorComponent`) and `DecomposeScalarExpression`. Both are shared infrastructure requiring careful testing.

See `memory/pre-linearization-benchmark.md` for full analysis.

## RESOLVED: SuperLU memory failure on moderate grids — nnz-based GMRES fallback

**Status:** Resolved
**Labels:** bug, solver, performance

**Problem:** IDA's sparse tier (2K < N ≤ 200K state variables) used SuperLU_MT for direct
Jacobian factorization. On moderate grids, SuperLU's LU fill-in (20–50× nnz) exhausted
memory and crashed:

- 32×32 × 12 slots = 12,288 unknowns → nnz ~172K → SuperLU crash
- 16×16 × 12 slots = 3,072 unknowns → nnz ~43K → SuperLU worked

**Workaround (now removed):** `examples/massive_gravity/run.sh` was reduced to 16×16 grid
(commit 6bac7f5). Restored to 32×32 as part of this fix.

**Fix:** Added `SUPERLU_NNZ_LIMIT = 100_000` to `tidal/solver/_types.py`. In
`configure_linear_solver()` (`tidal/solver/_setup.py`), after building the sparsity pattern,
if `pattern.nnz > SUPERLU_NNZ_LIMIT` the sparse tier falls back to FD GMRES (identical to
the N > 200K path, no `jactimes` callback, safe with `IDACalcIC`) with a `UserWarning`.
Systems below the limit continue to use SuperLU unchanged.

Note: The IDACalcIC regression in commit 7f3df3e was specific to the analytical `jactimes`
callback, not FD GMRES. The FD GMRES path (no `jactimes`) is unaffected.

**Relevant code:**
- `tidal/solver/_types.py` — `SUPERLU_NNZ_LIMIT = 100_000` added
- `tidal/solver/_setup.py:configure_linear_solver()` — nnz check + GMRES fallback
- `tests/test_analytical_jacobian.py:TestSuperLUNnzFallback` — 3 new tests

## OPEN: Energy measurement incorrect with position-dependent mass/potential terms

**Status:** Open (bug)
**Priority:** Medium
**Labels:** bug, measurement
**Identified:** 2026-03-09 during Gertsenshtein Phase F2 planning

**Problem**: `tidal measure --what energy` does not correctly account for spatially-varying
mass or potential terms. The Hamiltonian density computation in `_energy.py` assumes
translation-invariant coefficients; it evaluates coefficients at a single point (or as
constants) rather than integrating the position-dependent potential energy density over
the grid.

**Affected configurations:**
- Position-dependent mass terms: `m²(z) φ²` — common in plasma gradient / MSW crossing setups
- Localized Gertsenshtein coupling: effective mass term `B₀²κ²` on h_7 becomes position-dependent with localized B₀(z)
- Potential wells: `examples/scalar_potential_well/` (already documented in that example)

**Does NOT affect:**
- Conversion probability measurement (`--what conversion`) — measures amplitude ratios
- Conservation measurement (`--what conservation`) — measures relative change, not absolute energy

**Workaround**: Use `--what conversion` as primary validation metric for scattering setups.
For energy checks, use `--what conservation` (tracks relative ΔE/E rather than absolute value).

**Fix direction**: In `tidal/measurement/_energy.py`, the potential energy term should
evaluate `coefficient(x) * field(x)² ` as a grid array and integrate over the spatial grid,
analogous to how kinetic terms are handled. The `CoefficientEvaluator.resolve()` already
supports position-dependent coefficients — the fix is to use the grid-resolved array
(L2 cache) rather than a scalar when computing Hamiltonian contributions.

**Relevant files:**
- `tidal/measurement/_energy.py` — Hamiltonian density computation
- `tidal/measurement/_eval_utils.py` — coefficient evaluation utilities
- `tidal/solver/coefficients.py` — `CoefficientEvaluator` L2 spatial cache
- `docs/background_fields.md` — documents the limitation

## OPEN: Sponge-layer / absorbing boundary conditions

**Status:** Open (enhancement)
**Priority:** Medium
**Labels:** enhancement, solver, boundary-conditions
**Identified:** 2026-03-09 during Gertsenshtein Phase F2/F3 planning

**Problem**: TIDAL supports periodic, Neumann, Dirichlet, and Robin BCs only. For
open-domain scattering setups — wavepacket entering a localized coupling region and
exiting — outgoing waves either wrap around (periodic) or reflect off boundaries
(Dirichlet/Neumann), contaminating the conversion measurement.

**Affected use cases:**
- Gertsenshtein Phase F2: localized B₀(z) scattering (wavepacket enters magnetized region)
- Gertsenshtein Phase F3: magnetar/FRB (inward GW from large r, outgoing EM)
- Any finite-region scattering problem

**Workaround**: Use a very large domain with the coupling region in the center; terminate
simulation before outgoing waves reach boundaries. This is the pattern used in
`examples/coupled_scattering/`.

**Proposed implementation (Phase 1 — sponge layer)**:
- Add a spatially-varying dissipation term `-σ(x) ∂_t f` in boundary regions
- σ(x) ramps from 0 (inside domain) to σ_max (near boundaries) over a layer width
- Can be implemented via `[[background_fields]]` with coordinate-dependent σ(x)
  plus a new `first_derivative_t` coupling term in the Lagrangian
- Validate: reflected power < 1% at optimal σ_max

**Proposed implementation (Phase 2 — proper PML)**:
- Perfectly Matched Layer via complex coordinate stretching
- Requires split-field formulation; larger code change
- Industry standard (MEEP, FEniCS, Devito)

**Relevant files:**
- `tidal/solver/operators.py` (lines 40-182) — `SideBCSpec`, `_pad_axis()`, ghost-cell BCs
- `tidal/solver/grid.py` — `GridInfo` BC metadata
- `tidal/cli/_simulate.py` (lines 213-295) — CLI BC argument parsing
