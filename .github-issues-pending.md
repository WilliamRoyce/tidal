## Issue 1: Energy measurement missing sqrt|g| for curved coordinates

**Title:** Energy measurement fails for curved coordinate systems (missing metric determinant)

**Labels:** bug, energy-measurement

**Body:**

### Description

The energy conservation measurement (`tidal measure --what conservation`) fails for all curved coordinate examples, even when the metric is time-independent and energy should be conserved.

### Affected examples

| Example | max |dE/E| | Expected |
|---------|-----------|----------|
| polar_kg | 5.16e-02 | ~0 |
| sphere_kg | 8.16e-01 | ~0 |
| spherical_kg | 2.23e-01 | ~0 |
| cylindrical_kg | 1.99e-02 | ~0 |

Note: `de_sitter_kg` also fails (22%) but this is physically expected — the time-dependent metric (Hubble expansion) means energy is not a conserved quantity.

### Root cause

The Hamiltonian energy density integration in `_energy.py` does not weight by the metric determinant `sqrt|g|`. For curved coordinates:

- Polar: `sqrt|g| = r`
- Spherical: `sqrt|g| = r^2 sin(theta)`
- Cylindrical: `sqrt|g| = r`

The total energy should be `E = integral(H * sqrt|g| * dx)`, not `E = integral(H * dx)`.

### Note

All flat spacetime examples pass energy conservation (13/13 tested, all < 1e-3). The solver layer is correct — this is purely an energy measurement issue.

### Suggested fix

1. Store the metric determinant (or its square root) in the JSON spec
2. In `_compute_hamiltonian_from_canonical`, weight the energy density by sqrt|g| before spatial integration

## Issue 2: Energy measurement cannot evaluate background field functions in Hamiltonian

**Title:** Energy measurement ERROR for background field Hamiltonian terms

**Labels:** bug, energy-measurement, background-fields

**Body:**

### Description

When the Hamiltonian contains terms with coordinate-dependent background field functions (e.g., `gBV*vbdB0[t[], x[], y[]]`), the energy measurement fails because `CoefficientEvaluator` cannot evaluate Wolfram-style function expressions.

### Affected examples

| Example | Error |
|---------|-------|
| vector_background | `Cannot evaluate symbolic coefficient 'gBV*vbdB0[t[], x[], y[]]'` |
| proca_background | Energy FAIL (5.43e-03) — likely partial evaluation issue |

### Root cause

The `hamiltonian_terms` in the JSON contain `coefficient_symbolic` expressions with background field function calls like `vbdB0[t[], x[], y[]]`. These are Wolfram-syntax expressions that the Python `CoefficientEvaluator` cannot parse.

For the EOM terms, background field functions are resolved during the Wolfram derivation into coordinate-dependent expressions. But the Hamiltonian terms retain the function-call form.

### Suggested fix

Option A: During Wolfram export, expand background field functions in Hamiltonian terms to explicit coordinate expressions (as is done for EOM terms).

Option B: Add background field function evaluation to `CoefficientEvaluator` for energy measurement.
