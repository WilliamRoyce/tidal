## RESOLVED: SuperLU memory failure on moderate grids — nnz-based GMRES fallback

**Status:** Resolved
**Labels:** bug, solver, performance

**Problem:** IDA's sparse tier (2K < N ≤ 200K state variables) used SuperLU_MT for direct
Jacobian factorization. On moderate grids, SuperLU's LU fill-in (20–50× nnz) exhausted
memory and crashed:

- 32×32 × 12 slots = 12,288 unknowns → nnz ~172K → SuperLU crash
- 16×16 × 12 slots = 3,072 unknowns → nnz ~43K → SuperLU worked

**Workaround (now removed):** `examples/massive_gravity/run.sh` was reduced to 16×16 grid
(commit 6bac7f5). Restored to 32×32 as part of this fix.

**Fix:** Added `SUPERLU_NNZ_LIMIT = 100_000` to `tidal/solver/_types.py`. In
`configure_linear_solver()` (`tidal/solver/_setup.py`), after building the sparsity pattern,
if `pattern.nnz > SUPERLU_NNZ_LIMIT` the sparse tier falls back to FD GMRES (identical to
the N > 200K path, no `jactimes` callback, safe with `IDACalcIC`) with a `UserWarning`.
Systems below the limit continue to use SuperLU unchanged.

Note: The IDACalcIC regression in commit 7f3df3e was specific to the analytical `jactimes`
callback, not FD GMRES. The FD GMRES path (no `jactimes`) is unaffected.

**Relevant code:**

## OPEN: Energy measurement incorrect with position-dependent mass/potential terms

**Status:** Open (bug)
**Priority:** Medium
**Labels:** bug, measurement
**Identified:** 2026-03-09 during Gertsenshtein Phase F2 planning

**Problem**: `tidal measure --what energy` does not correctly account for spatially-varying
mass or potential terms. The Hamiltonian density computation in `_energy.py` assumes
translation-invariant coefficients; it evaluates coefficients at a single point (or as
constants) rather than integrating the position-dependent potential energy density over
the grid.

**Affected configurations:**

- Position-dependent mass terms: `m²(z) φ²` — common in plasma gradient / MSW crossing setups
- Localized Gertsenshtein coupling: effective mass term `B₀²κ²` on h_7 becomes position-dependent with localized B₀(z)
- Potential wells: `examples/scalar_potential_well/` (already documented in that example)

**Does NOT affect:**

- Conversion probability measurement (`--what conversion`) — measures amplitude ratios
- Conservation measurement (`--what conservation`) — measures relative change, not absolute energy

**Workaround**: Use `--what conversion` as primary validation metric for scattering setups.
For energy checks, use `--what conservation` (tracks relative ΔE/E rather than absolute value).

**Fix direction**: In `tidal/measurement/_energy.py`, the potential energy term should
evaluate `coefficient(x) * field(x)² ` as a grid array and integrate over the spatial grid,
analogous to how kinetic terms are handled. The `CoefficientEvaluator.resolve()` already
supports position-dependent coefficients — the fix is to use the grid-resolved array
(L2 cache) rather than a scalar when computing Hamiltonian contributions.

**Relevant files:**

- `tidal/measurement/_energy.py` — Hamiltonian density computation
- `tidal/measurement/_eval_utils.py` — coefficient evaluation utilities
- `tidal/solver/coefficients.py` — `CoefficientEvaluator` L2 spatial cache
- `docs/background_fields.md` — documents the limitation

## OPEN: Ghost detection for `tidal validate --stability`

**Status:** Open (future enhancement — requires Wolfram pipeline changes)
**Priority:** Low
**Labels:** enhancement, validate
**Identified:** 2026-03-09 during supervisor website review

**Problem**: Ghost detection from `canonical.hamiltonian_terms` in `tidal validate --stability`
is fundamentally unreliable and was removed. Ghost detection requires the physical kinetic
matrix K[i,j] after constraint reduction and gauge fixing — not the naive Hamiltonian
kinetic coefficients stored in the JSON.

**Why naive H kinetic coefficients fail:**

1. **Pure gauge theories (linearized GR)**: In Fierz-Pauli massive gravity, all dynamical
   metric components (h_3, h_4, h_5) have negative Hamiltonian kinetic coefficients (−0.5,
   −1.5, −0.5) even though FP is ghost-free. FP ghost-freeness comes from the mass term
   cancelling the Boulware-Deser ghost, not from kinetic positivity.
2. **Mixed theories (matter + gauge)**: Scalar matter fields have positive kinetic; metric
   perturbations have negative kinetic — both present causes false positives for all metric
   fields. The spacetime metric signature alone does not resolve this (the sign depends on
   gauge structure and ADM decomposition, not just the spacetime metric).

**Workaround**: Use dedicated tools such as xAct/Mathematica ghost-checking routines, or
manually verify ghost-freeness in a unitary/TT gauge.

**Future implementation paths:**

_Option A (Wolfram change) — Export `"kinetic_matrix"` and `"kinetic_matrix_symbolic"`_:
Add to the `"canonical"` JSON section the kinetic matrix K[i,j] computed from the quadratic
Lagrangian (coefficient of `∂_t φ^i ∂_t φ^j` in L, before E-L reduction). Check eigenvalues
of K — a negative eigenvalue indicates a ghost. Limitation: for gauge theories K may still
be indefinite due to gauge modes even in ghost-free theories; needs field-type information.

_Option B (Wolfram change) — Field type annotation_:
Add `"kind": "scalar" | "vector_spatial" | "vector_temporal" | "metric_perturbation"` to
each field in the JSON. The Python ghost check can then apply the correct expected-sign logic
per field class (e.g. skip metric perturbations, which are always ambiguous without gauge
fixing).

_Option C — Restrict ghost check to scalar sector only_:
Simplest if Option B is implemented — only check fields with `"kind": "scalar"` for
negative kinetic coefficients.

**Relevant code:**

- `tidal/cli/_validate.py` — `_run_stability_checks()` docstring documents the limitation
- `tidal/wolfram/ExportJSON.wl` — where kinetic matrix or field-type export would be added
- References: Boulware & Deser (1973) PRD 6:3368; Hassan & Rosen (2012) arXiv:1106.3344

## OPEN: Sponge-layer / absorbing boundary conditions

**Status:** Open (enhancement)
**Priority:** Medium
**Labels:** enhancement, solver, boundary-conditions
**Identified:** 2026-03-09 during Gertsenshtein Phase F2/F3 planning

**Problem**: TIDAL supports periodic, Neumann, Dirichlet, and Robin BCs only. For
open-domain scattering setups — wavepacket entering a localized coupling region and
exiting — outgoing waves either wrap around (periodic) or reflect off boundaries
(Dirichlet/Neumann), contaminating the conversion measurement.

**Affected use cases:**

- Gertsenshtein Phase F2: localized B₀(z) scattering (wavepacket enters magnetized region)
- Gertsenshtein Phase F3: magnetar/FRB (inward GW from large r, outgoing EM)
- Any finite-region scattering problem

**Workaround**: Use a very large domain with the coupling region in the center; terminate
simulation before outgoing waves reach boundaries. This is the pattern used in
`examples/coupled_scattering/`.

**Proposed implementation (Phase 1 — sponge layer)**:

- Add a spatially-varying dissipation term `-σ(x) ∂_t f` in boundary regions
- σ(x) ramps from 0 (inside domain) to σ_max (near boundaries) over a layer width
- Can be implemented via `[[background_fields]]` with coordinate-dependent σ(x)
  plus a new `first_derivative_t` coupling term in the Lagrangian
- Validate: reflected power < 1% at optimal σ_max

**Proposed implementation (Phase 2 — proper PML)**:

- Perfectly Matched Layer via complex coordinate stretching
- Requires split-field formulation; larger code change
- Industry standard (MEEP, FEniCS, Devito)

**Relevant files:**

- `tidal/solver/operators.py` (lines 40-182) — `SideBCSpec`, `_pad_axis()`, ghost-cell BCs
- `tidal/solver/grid.py` — `GridInfo` BC metadata
- `tidal/cli/_simulate.py` (lines 213-295) — CLI BC argument parsing

## OPEN: Plasma detuning (Gertsenshtein Phase F1) requires gauge-invariant mass mechanism

**Status:** Open (physics limitation)
**Priority:** Medium
**Labels:** enhancement, gertsenshtein, physics
**Identified:** 2026-03-09 during Phase F1 implementation

**Problem**: Adding a Proca-type photon mass `- omegaP2/2 * a[-mu] eta[mu, nu] a[-nu]` to the
full Einstein-Maxwell Lagrangian for the Gertsenshtein effect generates position-dependent
coefficients `B₀²κ²omegaP2 z²` on the graviton h_7 equations. This breaks the uniform plasma
model and is incompatible with periodic BCs.

**Root cause**: In TIDAL's xPert pipeline, the standalone perturbation field `a` (the photon
perturbation) is treated by xPert as a tensor with non-zero background value (equal to the
background gauge potential `Abar_y = -B₀z`). When the plasma mass `(omegaP2/2)|a|²` is expanded
to second order in the action `∫ √(-g) × L`, the term `(ε/2)Tr(h) × (omegaP2/2)|Abar|²` contributes
at O(ε²), giving position-dependent graviton mass `B₀²κ²omegaP2 z²`. Any gauge representation of
a transverse uniform B-field has `|Abar|² ∝ z²`, so no gauge choice avoids this.

**Why an effective scalar theory won't do**: The physical mixing modes (h\_+, a_y) reduce to scalars
in 1+1D — no different from the existing `coupled_scalars` example. The physics value of the plasma
example requires proper field types (tensor graviton, vector photon).

**What would be needed**:

_Option A — Stueckelberg mass_: Replace the Proca mass with a gauge-invariant Stueckelberg mechanism.
The Stueckelberg scalar `φ` absorbs the gauge degree of freedom; the mass term becomes
`-(omegaP2/2)(a_μ + ∂_μφ)²`. In unitary gauge (φ=0), this reduces to the Proca mass but without
the background-field coupling artifact. Requires adding a Stueckelberg scalar field to the theory.

_Option B — EOM-level medium_: Implement plasma as a medium term directly in the equations of
motion (adding `-omegaP2 * a_mu` to the photon EOM only, not derived from a Lagrangian term).
Would require a new `medium_terms` section in the JSON spec and CLI. Clean physics but bypasses
the Lagrangian derivation philosophy.

_Option C — Modified xPert pipeline_: In `_wls_matter_pert_truncation()`, explicitly zero the
background value of the perturbation field `gea` before xPert expansion, ensuring the plasma mass
is treated as purely O(ε²). This would require modifying the Wolfram pipeline to explicitly
declare `gea` as having zero background.

**Blocked by**: Needs investigation of whether Option C is feasible in xAct/xPert without
breaking other theories.

**Relevant code:**

- `tidal/cli/_derive.py:_wls_matter_pert_truncation()` (lines 847-883) — truncation logic
- `examples/gertsenshtein/theory.toml` — base Gertsenshtein (implemented)
- `docs/gertsenshtein.md` (Target 3) — physics description
- Raffelt & Stodolsky (1988, PRD 37:1237); Dandoy, Lella et al. (2024, arXiv:2406.17853)

## OPEN: Conversion measurement gives wrong results in curved coordinates (per-field energy ≠ physical energy)

**Status:** Open (investigation needed)
**Priority:** High
**Labels:** bug, measurement, curved-coordinates
**Identified:** 2026-03-11 during Gertsenshtein Phase F3a (spherical radial)

**Problem**: The conversion measurement `tidal measure --what conversion` uses per-field
Hamiltonian self-energy (kinetic + gradient + mass for each field separately) as the numerator
and denominator for P(t) = E_target(t) / E_source(0). In curved coordinates (e.g. spherical),
the per-field self-energy of component fields is dominated by coordinate artifacts, making the
conversion probability physically meaningless.

**Root cause**: In spherical coordinates, the component field h*{θθ} (= h_7 in TIDAL indexing)
relates to the physical gravitational wave strain ψ by h*{θθ} = r² × ψ. The self-energy of the
component field includes geometric factors:

- Kinetic: ½⟨(∂h_7/∂t)²⟩ = ½⟨r⁴(∂ψ/∂t)²⟩ — grows as r⁴ for outward-propagating wave
- Gradient: ½⟨(∂h_7/∂r)²⟩ — similarly grows geometrically

The Hamiltonian interaction energy includes Christoffel-connection terms (e.g. 2/r × ∂_r h
coupling) that exactly cancel this geometric growth, keeping the total Hamiltonian conserved.
However, the interaction energy mixes two physically distinct contributions:

1. **Actual graviton-photon coupling** (Gertsenshtein effect) — the physics we want to measure
2. **Geometric Christoffel self-coupling** — coordinate artifacts from component field → physical
   field mapping

There is no clean way to separate these from the Hamiltonian per-field decomposition alone.

**Observed numerics** (spherical dipolar, Bpeak=40, domain [5,80]):

- H*self(h_7) = 10274 (dominated by r² geometric amplification of h*{θθ})
- H_interaction = -10274 (Christoffel corrections cancel geometric self-energy)
- H_total ≈ 0 (correctly conserved)
- P_measured = E_self(a_2) / E_self(h_7, t=0) = 0.000025
- P_Boccaletti = sin²(κBpeak z0³/(4R²)) ≈ 0.147

The conversion measurement is off by ~6000× because it divides by the coordinate-inflated
h_7 self-energy rather than the physical graviton energy.

**Note**: The volume-weight fix (same session) ensures the per-field energies correctly include
the spatial volume element √|g_spatial| = r² for the energy integral. This is necessary but
not sufficient — the fundamental issue is that component field self-energy ≠ physical field
energy in curved coordinates.

**What works correctly**:

- Flat-space conversion measurements (component fields = physical fields)
- Total Hamiltonian conservation in curved coordinates
- Energy measurement per-field decomposition for flat spacetimes

**Investigation needed**:

1. **Physical field extraction**: Define "physical energy" via gauge-invariant quantities.
   For gravitons in TT gauge: E*phys = ½∫ r² [(∂ψ/∂t)² + (∂ψ/∂r)²] dr where ψ = h*{θθ}/r².
   For photons: similarly extract physical transverse EM field from component a_θ.
   Requires knowing the metric-to-physical-field mapping per field type.
2. **Flat-space proxy**: Use flat Minkowski metric with the same B-field profile
   (dipolar 1/z³) — component fields = physical fields, conversion measurement works.
   Validates the same Boccaletti formula without curved-coordinate complications.
   (Implementation: `examples/gertsenshtein/theory_dipolar.toml` — flat space proxy.)
3. **WKB conversion measurement**: In the WKB limit (k >> 1/r), the spherical wave equation
   for u = r×h reduces to the flat-space form. The conversion probability could be measured
   from the WKB-reduced variables u_grav and u_photon directly. Requires post-processing of
   the simulation output with the r-dependent field rescaling.

**Immediate workaround**: Use the flat-space dipolar theory (`theory_dipolar.toml`) for
Boccaletti validation. The spherical coordinate theory is correct for the PDE evolution
(the equations are mathematically right), but the conversion measurement needs a different
approach for curved metrics.

**Investigation direction — coordinate-independent per-field energy**:
The total Hamiltonian H is a scalar (coordinate-independent). The issue is that the
per-field decomposition H = Σ H*self(field_i) + H_interaction depends on which field
variables are used. For tensor fields in curved coordinates, component variables include
coordinate factors (e.g. h*{θθ} = r² ψ for the physical strain ψ). The self-energy of
the component variable is NOT the physical field energy.

A coordinate-independent per-field energy decomposition would require:

_Option 1 — Physical field extraction_:
Define physical (gauge-invariant) variables:

- Graviton: ψ = h\_{θθ}/r² (physical TT strain), energy density ∝ ⟨(∂ψ/∂t)²⟩ r²
- Photon: similarly, extract physical transverse EM field from component a_θ
- Requires a "physical_field_map" in the JSON spec: `{"h_7": "h_7 / x[]^2"}`
- The conversion measurement would use P = E_phys(a)/E_phys(h, t=0)

_Option 2 — Invariant norm from the field-space metric_:
For a multi-field theory with fields φ^I living on a field-space manifold with metric
G_IJ (from the kinetic terms in the Lagrangian), the gauge-invariant energy is:
E = ½ G_IJ ⟨∂_t φ^I ∂_t φ^J⟩ + ½ G_IJ ⟨∂_i φ^I ∂_i φ^J⟩
The field-space metric G_IJ diagonalizes the kinetic term and correctly weights each
component. This is already partially implemented in the canonical Hamiltonian evaluation
(which sums over hamiltonian_terms with their field-space coefficients), but the per-field
split uses `compute_field_energy` which ignores cross-kinetic terms.

_Option 3 — WKB variable transformation_:
In the WKB limit (k >> geometric potential terms), define u_i = √(g_spatial) × h_i^phys.
The u_i satisfy flat-space wave equations plus coupling. The self-energy of u_i IS the
physical field energy, invariant under coordinate changes. Requires post-processing the
simulation output with coordinate-dependent rescaling factors.

**Status of investigation**: Options 1 and 3 are most promising. Option 3 is simplest to
implement (post-processing only, no pipeline changes) but only valid in WKB limit.
Option 1 is general but requires extending the JSON spec and \_energy.py.

**Relevant files:**

- `tidal/measurement/_conversion.py` — conversion probability measurement
- `tidal/measurement/_energy.py` — per-field Hamiltonian energy decomposition
- `examples/data/gertsenshtein_radial.json` — spherical dipolar theory (derived)
- `examples/gertsenshtein/theory_dipolar.toml` — flat-space proxy (workaround)
- `docs/gertsenshtein.md` — physics documentation

## OPEN: Optimize canonical Lagrangian decomposition (24 min for flat Einstein-Maxwell)

**Status:** Open (performance)
**Priority:** Medium
**Labels:** performance, derivation, wolfram
**Identified:** 2026-03-12 during derivation performance profiling

**Problem**: The canonical Lagrangian decomposition via `DecomposeScalarExpression` is the
dominant cost in the derivation pipeline — 24 of 40 minutes for flat 4D Einstein-Maxwell
(`examples/gertsenshtein/theory.toml`). This phase decomposes 34 additive Lagrangian terms
independently via `DecomposeScalarExpression`, each going through the full
`SeparateFieldMetrics` → `ToBasis` → `TraceBasisDummy` → metric evaluation pipeline.

Previously (~10 min total) the canonical pipeline was skipped via a fast path; since commit
`58dcac4` the full Legendre transform always runs for correct coordinate-invariant energy
measurement.

**Profiling data** (flat 4D Einstein-Maxwell, 2026-03-12):

| Phase | Time | Notes |
|-------|------|-------|
| EOM h decomposition (6 comp) | ~14 min | 332 & 226 terms per comp |
| EOM a decomposition (4 comp) | ~1.5 min | 99 terms per comp |
| Linearization total | ~16 min | Includes xPert + gauge |
| **Canonical Lagrangian decomp** | **~24 min** | **34 additive terms, DOMINANT** |
| Legendre + parse | <1s | Trivial |

The EOM pass decomposes the **equations of motion** (`VarD[L]`) — a fundamentally different
algebraic object from the Lagrangian. Caching the EOM decomposition result for reuse in the
canonical path is not possible. Wolfram kernel state (Christoffels, metric DownValues,
background field DownValues) IS already shared between passes via `Share[]`.

**Investigation directions**:

_Option A — Shared sub-expression caching in `DecomposeScalarExpression`_:
Many of the 34 Lagrangian terms share the same tensor structure (field heads, index patterns,
metric contractions). The `ToBasis` + `TraceBasisDummy` pipeline repeats identical index
summation work across similar terms. A structural hash of each term's tensor skeleton could
identify groups that share the same decomposition, with only the scalar prefactor differing.
Decompose once per group, then multiply by the per-term coefficient.

Complexity: High — requires classifying abstract tensor terms by structure in Wolfram, which
means pattern-matching on xAct's internal representation. Potential 2-5x speedup for theories
with repetitive Lagrangian structure (Einstein-Maxwell: 34 terms from ~10 distinct structures).

_Option B — Combine EOM and canonical decomposition into a single pass_:
Instead of decomposing the EOM and Lagrangian separately, decompose the Lagrangian FIRST,
then derive the EOM from the component-form Lagrangian using `D[lagComp, field_comp]`.
This eliminates the abstract-index `VarD` + `DecomposeToComponents` pass entirely.

Trade-off: VarD at the abstract level is more robust (handles gauge symmetry, integration
by parts automatically). Component-level variation would need explicit IBP handling and
careful tracking of boundary terms. May introduce subtle bugs for theories with non-trivial
gauge structure.

Complexity: High — fundamental pipeline restructuring. Potential 1.6x speedup (eliminate
16 min of EOM decomposition, canonical becomes the only decomposition).

_Option C — Incremental `Expand[]` in `BatchedTraceBasisDummyWithMetric`_:
Profiling shows `Expand[]` inside `BatchedTraceBasisDummyWithMetric` is the dominant
sub-operation. Currently `Expand[]` is called on the full summed result after
`TraceBasisDummy`. An alternative: `ExpandAll` only on newly-created tensor contractions,
or `Simplify` with a targeted complexity limit.

Complexity: Medium — requires understanding which sub-expressions in the output of
`TraceBasisDummy` benefit from expansion and which create unnecessary intermediate growth.

_Option D — Wolfram `FunctionCompile` for metric evaluation_:
The metric evaluation step (`EvaluateMetricComponents`) dispatches on component indices
to substitute metric values. For diagonal metrics (most cases), this is a pure lookup:
`g_{ii} → value_i`, `g_{ij} → 0` for i≠j. Wolfram's `FunctionCompile` could bypass the
pattern matcher entirely for this step, replacing symbolic rule application with compiled
dispatch. Low risk, focused optimization.

Complexity: Low-Medium — need to verify FunctionCompile handles the output format of
TraceBasisDummy correctly. Potential 1.5-2x speedup on the metric evaluation sub-step.

_Option E — Pre-decompose Lagrangian before xPert expansion_:
For linearization theories, the Lagrangian is written in abstract-index form, expanded to
2nd order by xPert, then decomposed. If the NON-expanded Lagrangian were decomposed to
components first, the 2nd-order expansion could be done at the component level (faster,
since component expressions are scalar). However, xPert's `Perturbation[]` requires
abstract tensors — it cannot operate on component expressions.

Complexity: Very high — would require reimplementing perturbation theory at the component
level. Not recommended unless all other options prove insufficient.

**Mitigation already in place**: Derivation caching (`--force-derive` to bypass) means the
40-minute cost is paid only once per theory. Subsequent runs with unchanged TOML hit the
SHA-256 cache and return instantly. This makes the optimization lower-priority for most
workflows but still important for theory development iteration.

- `tidal/cli/_derive.py:_wls_canonical_hamiltonian()` (lines 2402-2590) — canonical decomposition loop
- `tidal/wolfram/ComponentDecompose.wl:DecomposeScalarExpression()` (lines 880-973) — scalar decomposition pipeline

## Compute Hamiltonian after constraint elimination in Wolfram (Issue 7)

**Status:** DONE (implemented in `_wls_constraint_elimination()`)

Constraint elimination now runs in Wolfram BEFORE the Legendre transform: constraints are detected in `fieldEquations`, substituted into `lagComp` via exact symbolic algebra, and the Hamiltonian is computed for surviving fields only. Two constraint types supported:

1. **Gradient-zero**: `gradient(f)=0` → `f=0` (periodic BCs + zero IC)
2. **Degenerate algebraic**: self-field cancels (coeff≈1.0), residual constraint solved for dep field with largest |coefficient| (e.g., `h_9=h_4+h_7+h_9` → `0=h_4+h_7` → `h_4=-h_7`)

Nonlinear constraint warning added (cannot occur in linearized regime but aids debugging). Legacy Python string-algebra path (`_substitute_hamiltonian_constraints`) guarded with `wolfram_constraint_elimination` flag for backward compatibility with pre-existing JSONs.

**Verified:** GW 1D re-derived — Hamiltonian terms match old result exactly, |dE/E|=2.25e-08. All 1508 tests pass.

**Future cleanup:** Remove legacy Python code path (7 functions in `reduction.py`) after all examples are re-derived.

**Relevant code:**
- `tidal/cli/_derive.py:_wls_constraint_elimination()` — Wolfram constraint detection + substitution
- `tidal/symbolic/reduction.py:eliminate_degenerate_constraints()` — Python side (skips H substitution when Wolfram handled)
- `tidal/symbolic/json_loader.py:CanonicalStructure` — `wolfram_constraint_elimination` flag
