**Program:** TIDAL → Cosmology (`docs/COSMOLOGY_PROGRAM.md`). Workstream: **WS6 (#495)**.
**Design authority:** `docs/cosmology/spectrum_design.md` (H6) — read it first, in full.
It supersedes the older #360 plan as the starting point.
**Mode:** the program's **first engineering handoff** — this one installs software and runs

**Artifacts:** a working Stage-1 pipeline + measured costs, reported back for the

## Why this exists

H6 settled the *design*: symbolic PSALTer runs **once per Lagrangian structure** to discover
structure (gauge ranks, massive/massless partition, constraint matrix, closed-form conditions),
and a JAX evaluator then gives per-sample verdicts in order-milliseconds. Stage 2 (the
evaluator) cannot be built until Stage 1 actually emits its contract. That is this task.

## Hard constraints — read before starting

- **ONE `wolframscript` at a time.** Single-engine licence, project-wide. Never run
  derivations in parallel, and check nothing else is running first.
- **Wolfram is Stage-1 only.** Per the standing rule, no symbolic manipulation happens
  Python-side; per the *cosmology* policy, Wolfram runs **at derivation time only**, never on
  a per-sample path.
- **`third_party/WolframEngine_14.3.0_LIN.sh`** is in-repo. PSALTer needs Mathematica 14+,
  xAct ≥ 1.2, and Inkscape for spectrograph output.
- **Provenance (D6).** Barker has explicitly permitted using his code; copy freely, record in
  docstrings what came from where. Attribution is settled with the supervisor at publication.
  License is a **release blocker recorded on #495**, not an implementation blocker.
- Work in a worktree off `feat/cosmology-program`; report the branch. Never `git checkout` in
  the shared working directory.

## Tasks

### 1. Install and verify PSALTer

Install Wolfram Engine + xAct + PSALTer (`wevbarker/PSALTer`) and the supplemental tooling
from `wevbarker/SupplementalMaterials-2607` (`WolframLanguage/ParticleSpectroscopy.m`,
`JuliaExport.m`). Verify by **reproducing a published spectrograph** — TorC's is the natural
target since both its inputs and outputs are in `literature/2507.09228/`
(`ParticleSpectrographTorCPGT.pdf`, `ParticleSpectrographTorCECT.pdf`), and the paper gives
the theory explicitly (its eq. `TorCLagrangian`) plus the three unitarity conditions
`λ ≥ 0, μ < 0, (ν+2μ)(ν−μ) > 0` as the answer. **Recall one of those three is a *massless*
residue condition** — so this doubles as a first check that the massless sector is reachable.

Record the install route precisely enough to repeat (a script under `scripts/`, not prose).

### 2. Build the spectrum derivation branch

Per design §4.5 this is **a second derivation from the shared input model, not a fork of the
solver branch**: Minkowski vacuum, background fields absent, product is the quadratic
**Lagrangian** in abstract index form (never evaluated to components), in Barker conventions
`(+,−,−,−)`, `ε₀₁₂₃ = +1`. The solver branch goes straight to the EOM and does not detour
through this.

Shared and convention-free (decide once, consume twice): config parse/validation, field
declarations and symmetry classification, coupling roster, term-level Lagrangian structure,
gauge declarations, scope guards. Duplicated: only the convention-laden symbolic work.

Follow **#513** — emit ecosystem conventions **natively**, no conversion layer.

### 3. Write our exporter — the part PSALTer does not give us

Design §6.1 is the contract. The committed `.wxf` files were decoded on 2026-09-03; build to
what they actually contain, not to what the docs imply:

- **Explicit per-state `J^P` labels. Position is never a label.** This is a *demonstrated
  defect*, not a hypothetical: `…A23Theory.wxf` exports three `WaveOperator` blocks of dims
  2/4/2 (`2·1 + 4·3 + 2·5 = 24` ✓) which are **`J`-blocks mixing both parities**, with the
  `J=1` block visibly `2+2` block-diagonal. The released JAX
  `SPIN_LABELS = ["0+","1-","2+","3-",…]` positional convention is therefore wrong even for
  the release's own test theory. Parity feeds the Hermitization `diag(1,−1)` and hence every
  ghost verdict, so a mislabel is a silent wrong answer.
- **Coupling-linear coefficient tensors, not symbolic matrices**: each block as
  `A[n,0] + Σᵢ cᵢ·A[n,i]` with `A` numeric. Keeps expression swell Wolfram-side, gives exact
  free `∂M/∂c`, and means no sympy/lambdify on the per-sample path.
- **Read association keys and normalize; never hardcode.** Key names vary (plural vs
  singular) between exports, and several slots come back as unevaluated placeholder symbols —
  treat a bare symbol as *absent*. `…VectorTheory.wxf` and `…A23Theory.wxf` are small and are
  ready-made unit-test fixtures; use them as such.
- Handle both populated and degenerate cases: `…TDiffTheory.wxf` has closed-form
  `UnitarityConditions` and a populated `ComponentSourceConstraints`;
  `…TensorTheory.wxf` has `UnitarityConditions = Text["(Demonstrably impossible)"]` and an
  empty constraint matrix. Both are legal outputs.
- Export `z_degree` as Stage-1 metadata (or probe it at random coupling points), and document
  the non-generic-point failure mode.

### 4. Measure `Method→"Hard"` cost on a PGT+EM theory

**Currently unmeasured and flagged in the design (§12) as the top open risk.** TorC's
spectrographs prove the method terminates on a PGT theory; nobody has timed it on the
PGT+EM-sized blocks we care about. Measure it on a real theory from the campaign roster.

This is a **go/no-go input for the whole two-stage architecture**: Stage 1 is once-per-
structure, so minutes are fine and hours are survivable, but if it does not terminate on
PGT+EM the design needs revisiting. Report the number either way, and if it fails to
terminate, say so plainly rather than working around it.

Also record: missing-coupling failure behavior, and whether `k⁴` sectors (`b5·R̃²`) fall
outside the degree-≤2 contract as the old #360 plan anticipated.

## Success criteria

- A published spectrograph reproduced (TorC), including its massless residue condition.
- Stage-1 export emitted for at least one campaign theory, satisfying the §6.1 contract with
  explicit `J^P` labels.
- `Method→"Hard"` wall time on PGT+EM **measured and reported**, with a clear verdict on
  whether the architecture holds.
- Install route reproducible from a committed script.
- The two small `.wxf` files wired as unit-test fixtures.

## Addenda (H6, post-design — additive, nothing above changes)

**A fully-local fallback verification theory, if TorC's sources prove awkward to obtain.**
The TorC paper points at the PSALTer repo for its spectroscopy sources, so Task 1 may involve
a hunt. `literature/2506.02111/` already contains a complete, self-contained alternative
(verified present 2026-09-03): `ScalarParityViolatingPGT.tex` (the model, as a literal
`ParticleSpectrum[...]` input listing), `TetradPerturbation.tex` + `SpinConnection.tex` (the
`DefField` declarations), `LoadPSALTer.tex`, and the published output
`ParticleSpectrographScalarParityViolatingPGT.pdf`. Its own published **massless** condition
(`c₁ < 0`) is the answer to check against — so it keeps Task 1's visible-failure property (a
massive-only install fails loudly) with **zero fetching**. Use TorC if its sources are
readily available; otherwise this, without treating the substitution as a compromise.

**Task 4's `b5·R̃²` item is a GUARD TEST, not roster support.** Curvature-squared terms are
**excluded from the term roster by user decision** (`spectrum_design.md` §2, lines 83–84 —
their perturbation theory is problematic and we will not sample them). Checking that the
degree-≤2 contract *refuses* `b5` is precisely how the guard is verified. Record the outcome
as **"guard fires correctly"** — do not wire `b5` in as a supported case on the strength of
having tested it.
