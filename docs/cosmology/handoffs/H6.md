## Context

Purpose: a fast numerical particle-spectrum check (pole masses, residues, ghost/tachyon
verdicts) so vacuum-sick theories are screened out before any cosmology compute — exactly
how the TorC paper used the *symbolic* PSALTer for its one theory. We need the
*numerical* version because we sample arbitrary Lagrangians and coupling values, the
regime where symbolic computation fails by expression swell (arXiv:2606.30785; supervisor
Barker said the same in the 2026-08-28 meeting).

**Permissions and provenance (user-confirmed):** the author has explicitly said we can
use his code to write our own. Take heavy, deliberate inspiration — reading and copying
is fine. Record provenance in docstrings (what came from where); formal attribution is
settled with the supervisor at publication time. This is NOT a clean-room
reimplementation; the released versions are cross-checks.

## Task

1. **Understand the algorithm** from the paper + both code versions: wave-operator
   construction per spin-parity sector (`M(Def) = M0 + Def·M1 + Def²·M2`), saturated
   propagator, pole finding, residue signs, gauge/null-direction handling, the
   degree-≤2-in-Def contract (`split_def_powers` — k⁴ sectors like `b5·R̃²` are outside
   it; likely auto-sick per Ostrogradsky, see #164/#222).
2. **Design our module**: which parts adapt directly from the JAX code (with provenance
   notes), which need rework to consume *TIDAL's* theories (the Wolfram-side export —
   the old plan's `ExportPSALTer.wl` design, F3, emitting a standalone PSALTer run and/or
   WXF from the TOML Lagrangian at Minkowski vacuum with background fields zeroed).
   Reconcile with H4's package layout.
3. **Define the validation set**: (a) reproduce the three hand-derived
   Lin–Hobson–Lasenby stability inequalities for TIDAL's sector
   (`docs/tex/pgt_stability_priors.tex`); (b) numerical agreement with the
   SupplementalMaterials JAX version on pole masses/residues for shared test theories;
   (c) the TorC spectrograph results (`literature/2507.09228/`
   `ParticleSpectrographTorCPGT.pdf`) as a cross-check target.
4. **Integration points**: how the verdict gates the cosmology pipeline (screen before
   compute; `run_status` tagging in inference), per the old plan's Phase 2/3 shape but
   re-targeted at the new package.
